%
% Directional connectors attach to node borders orthogonally. Use the middle

% ---------------------------------------------------------------------------
% Arrow and connector semantics
% ---------------------------------------------------------------------------
%
% Every directional connector is one TikZ path whose arrow tip is part of that
% same path. Never draw a line and place a separate arrowhead on top of it.
% Off-axis routing is orthogonal (Manhattan-style) using |- / -| and explicit
% border ports. A diagonal is permitted only when the geometry or semantics
% genuinely require it; it is never the default shortcut between boxes.

\tikzset{
  mqtt connector/.style={line cap=butt,line join=round},
  mqtt flow/.style={mqtt connector,-{Stealth[length=2.2mm,width=1.5mm]},draw=MQLine,line width=.8pt},
  mqtt data flow/.style={mqtt connector,-{Stealth[length=2.2mm,width=1.5mm]},draw=MQDataPlaneLine,line width=.9pt},
  mqtt control flow/.style={mqtt connector,-{Stealth[length=2.2mm,width=1.5mm]},draw=MQControlLine,line width=.9pt},
  mqtt observation/.style={mqtt connector,-{Stealth[length=2.0mm,width=1.4mm]},draw=MQLine,line width=.75pt,dashed},
  mqtt handoff/.style={mqtt connector,-{Stealth[length=2.3mm,width=1.6mm]},draw=MQCrossLane,line width=1pt},
  mqtt association/.style={mqtt connector,draw=MQBorder,line width=.7pt},
  mqtt dependency/.style={mqtt connector,-{Stealth[length=2.0mm,width=1.4mm]},draw=MQLine,line width=.7pt,dashed}
}

% ---------------------------------------------------------------------------
% Canonical publication rules
% ---------------------------------------------------------------------------
%
% 1. Figure .tex + this style file are canonical.
% 2. Generated SVGs are never hand-edited.
% 3. SVG is the publication format for technical diagrams.
% 4. PNG is reserved for genuine runtime/UI evidence or raster-only input.
% 5. Desktop/mobile may share semantics but use independently art-directed geometry.
% 6. No arrow without real directional semantics.
% 7. Dashed arrows mean observation/secondary relationship, not primary flow.
% 8. Containers denote real process/runtime/trust/configuration/lifecycle boundaries.
% 9. Color never carries the only semantic distinction.
% 10. Horizontal sequences use the canonical horizontal rhythm; avoid arbitrary x-spacing.
% 11. Rounded corners follow the semantic radius scale; avoid one-off radii.
% 12. Flat rendering is the default; elevation/shadows are explicit and justified.
% 13. Prefer explicit anchors/ports and orthogonal routing where clarity improves.
% 14. Preserve readable text size at actual GitHub desktop/mobile rendering widths.
% 15. Every directional connector is a single path with its arrowhead attached to that path; detached or separately placed arrowheads are forbidden.
% 16. Connectors leave and enter box borders orthogonally at 90 degrees. Use the middle of the relevant border by default.
% 17. If several connectors share one border, distribute their attachment ports evenly across that border on both source and destination sides.
% 18. Do not use unmotivated diagonal connectors. Use orthogonal Manhattan routing between ports unless a diagonal has a specific semantic or geometric justification.
